# E-Voice 故障排除指南

## 输入法风格实时语音识别问题

### 常见问题及解决方案

#### 1. 连接问题
- **问题**：点击"连接"没有反应或连接失败
- **解决**：
  - 确保后端服务已启动：`python rest.py`
  - 检查端口8210是否被占用
  - 在WSL环境中，使用`172.31.77.180:8210`地址
  - 查看浏览器控制台是否有WebSocket错误

#### 2. 麦克风权限问题
- **问题**：浏览器提示麦克风权限被拒绝
- **解决**：
  - 点击浏览器地址栏的🔒图标，允许麦克风访问
  - 确保系统麦克风设备正常工作
  - 使用HTTPS协议访问（某些浏览器要求）

#### 3. 识别结果问题
- **问题**：说话后没有识别结果显示
- **解决**：
  - 检查音频质量：确保环境安静，麦克风距离适中
  - 观察日志中的RMS值（>0.01表示有音频输入）
  - 说话清晰，停顿明确（1.5秒停顿触发句子确认）

#### 4. 句子不能确认问题
- **问题**：实时区域有文字，但不转移到确认区域
- **解决**：
  - 说完话后停顿足够时间（1.5秒）
  - 避免背景噪音干扰
  - 可以手动点击"清空结果"重置状态

#### 5. 重复显示buffer内容
- **问题**：确认区域显示重复的累积内容
- **解决**：
  - 这应该已经修复，如果仍出现请刷新页面
  - 点击"清空结果"重置会话状态
  - 检查后端日志确认句子检测逻辑

### 调试信息

#### 前端调试
1. 打开浏览器开发者工具（F12）
2. 查看Console标签页的错误信息
3. 观察Network标签页的WebSocket连接状态
4. 启用"显示详细日志"查看识别过程

#### 后端调试
1. 查看终端输出的音频处理日志
2. 注意"音频块处理成功"的amplitude值
3. 观察句子完成检测的触发情况

### 预期行为

#### 正常的输入法风格工作流：
1. **开始录音**：实时区域显示"正在监听..."
2. **说话时**：实时区域显示当前句子（蓝色斜体）
3. **停顿1.5秒**：句子移动到确认区域（黑色正体）
4. **实时区域清空**：准备下一句话
5. **继续说话**：重复上述过程

#### 音频质量指标：
- **RMS > 0.01**：有效音频输入
- **amplitude < 1.0**：正常音频范围
- **格式：PCM 16位 16kHz**：最佳识别效果

### 环境要求

#### 服务器端：
- Python 3.12+
- 已安装requirements.txt中的依赖
- soundfile, torch等库正常工作

#### 客户端：
- 现代浏览器（支持AudioContext）
- 麦克风设备和权限
- 稳定的网络连接
