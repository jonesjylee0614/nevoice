# 实时语音识别优化方案说明

## 设计目标对照

| 需求点 | 当前实现 | 说明 |
| --- | --- | --- |
| 实时纠错 | WebSocket `partial` 消息携带 `text_state.confirmed_text` 与 `candidate_text`，前端拆分成固定片段与临时候选。 | 通过 `RealtimeSpeechSession` 统一维护确认句子队列，任何增量更新都会刷新候选文本并在 UI 中淡化展示。 |
| 自动断句与标点 | `check_sentence_complete` 结合静音时长与语义完整度触发 `finalize_current_sentence`，`predict_punctuation` 根据停顿插入句号/逗号/问号。 | 完成定稿后会锁定句子并清空实时缓冲，新的音频流直接进入下一句。 |
| 前端展示 | 结果面板划分为“实时内容”和“确认文本”，已确认句子列表与候选文本分色显示，元数据（段号、修订号、置信度）同步更新。 | 用户可以直观看到纠错过程及最终定稿，避免“一刀切”体验。 |
| 数字与专有名词 | `format_numbers` 覆盖百分比、量词、中文数字与小数混读；热词替换在 `normalize_text` 中兜底。 | 单元测试覆盖典型数字、人口、日期等场景，保证改写准确。 |

## 整体方案概览

### 服务端流水线

1. **音频缓冲管理**：`RealtimeSpeechSession` 接收音频块，动态估计静音时长与语义完整性，及时触发断句。
2. **增量识别与纠错**：
   - 首选 FunASR 流式模型输出实时候选，必要时回退离线识别。
   - 候选文本通过 `normalize_text` 标准化（包含数字格式化、热词替换、语气词清理）。
   - 长停顿时 `_maybe_apply_interim_punctuation` 构造一次“合成 partial”，提前给出断句预览。
3. **定稿阶段**：
   - `finalize_current_sentence` 汇总流式/离线结果，调用 `predict_punctuation` 自动补标点，再经过 `_auto_correct_text`（可选中文纠错）。
   - 句子写入 `confirmed_sentences` 队列并生成 `final` 消息，历史句子不再回删。
   - `_register_final` 保留近五条记录用于去重，避免重复播报。
4. **消息格式**：
   - `partial`：包含 `text`、`confidence`、`segment_id`、`revision`，以及 `text_state`（confirmed/candidate/full）。
   - `final`：附带 `selected_source`、`auto_correction` 等元数据，前端可选用来渲染标签或调试。

### 前端交互

1. **状态拆分**：
   - `partialConfirmedText` 与 `partialCandidateText` 分别对应锁定段与活跃候选。
   - `finalSentences` 维护整个会话已确认句子列表，`computed` 过滤空串后渲染。
2. **可视化策略**：
   - 实时区块采用淡色背景、候选文本斜体 + 主色，突出仍可能变动的部分。
   - 元数据区展示段号、修订次数、置信度，让调试人员能快速定位问题。
3. **日志与状态面板**：实时写入 `logs` 缓冲，支持复制/下载；轮询 `/ws/status` 了解活跃会话、消息数等指标。
4. **录音与传输**：
   - 支持配置音频块间隔、静音检测、可选自适应增益（AGC），平衡延时与识别稳定性。
   - 断线后自动心跳重连，确保长时间会话稳定。

### 数字与文本规范化

- **百分比表达**：`百分之N` → `N%`，并保留“以上/以下”等限定词。
- **量词与单位**：识别“万/亿”缩写，支持亩、吨、人次、公里等常用后缀。
- **日期时间**：对“二零二四年”“一月一日”做数字化处理，增强可读性。
- **去噪清理**：`smooth_oral_text` 去除重复口头语、冗余空白，保持句子简洁。

## 测试与验证

### 自动化测试

- `python -m unittest e-voice.tests.test_text_processing`：覆盖数字、百分比、日期等格式化场景。
- `python -m unittest e-voice.tests.test_session_pipeline`：模拟定稿流程，验证自动断句+数字规范化后会锁定句子并清空实时缓冲。

> 注：执行 `test_session_pipeline` 前需安装轻量依赖 `numpy`、`soundfile`、`pydub`（均已在当前环境中安装）。

### 手工/模拟测试建议

1. 启动后端（示例）：
   ```bash
   cd e-voice
   python app.py  # 或按项目实际启动脚本
   ```
2. 使用提供的 `e-voice/tests/websocket_test.py` 连接 WebSocket，先发送 `start`，随后逐帧推送本地音频数据或模拟 `chunk` 消息，观察 `partial`/`final` 响应结构。
3. 前端运行 `npm run dev`，在“实时语音识别”页面：
   - 观察实时区域中文本的动态修正、斜体候选与置信度。
   - 停止讲话 1~2 秒，确认句子是否补齐标点并锁定到“确认文本”区域。
   - 输入含数字（如“百分之五以上”“一百六十七万亩”）的语音，检查格式化结果。
