# 文档规范

本规范用于统一 e-voice 项目在 `e-docs/` 目录下的文档撰写、存放与更新方式，确保团队成员无需查阅源码即可通过文档掌握系统全貌与最新变更。【F:e-docs/README.md†L1-L3】

## 1. 文档分类与存放

| 类别 | 说明 | 存放路径 |
| --- | --- | --- |
| 项目全景 | 覆盖系统组成、部署架构、端到端流程，需包含模型与数据流说明。 | `e-docs/2025-项目指南/`（示例：《总体架构与说明》） |
| 子系统详解 | 针对单个服务（Python、Go、前端等）拆解目录、关键流程、配置项与常见问题。 | `e-docs/2025-项目指南/` 下以 “子系统-名称详解.md” 命名。 |
| 历史与专题 | 旧版本记录、专项调研、问题排查等，可放置在 `e-docs/<子目录>` 并在 README 中索引。 |

> 新增文档时需在相关总览文档中补充链接，以保持可发现性（示例：《总体架构与说明》的“文档体系”章节列出子文档）。【F:e-docs/2025-项目指南/总体架构与说明.md†L120-L137】

## 2. 子系统文档模板

编写子系统详解文档时，推荐遵循以下结构：

```markdown
# <服务名称> 详解
1. 服务概述（职责、运行形态、端口、依赖）
2. 技术栈与依赖（表格列出核心包、版本、用途）
3. 配置与运行环境（关键配置项、环境变量）
4. 目录结构与职责（表格说明目录/模块职责）
5. 核心功能与流程（必要时使用序列图/流程图）
6. 数据交互与外部依赖
7. 运行与部署步骤
8. 观测与安全（日志、监控、鉴权）
9. 常见问题与排查
10. 更新记录（可选）
```

- 每个小节需结合源码引用，使用 `【F:文件路径†L起-L终】` 形式标注依据。若引用终端输出或脚本结果，可使用 `【chunk†Lx-Ly】`。所有引用需指向当前提交中的文件。  
- 描述模型相关逻辑时，必须说明模型名称、加载位置以及如何确认运行中的模型（例如查看日志或配置）。

## 3. README 模板

服务仓库根目录的 README 应包含以下内容：

1. **项目简介**：一句话说明职责、主要能力。
2. **快速开始**：安装依赖、启动命令、环境变量示例。
3. **配置说明**：关键配置项及默认值。
4. **运行与调试**：常用脚本、常见命令。
5. **日志与排查**：日志位置、监控入口。
6. **常见问题**：列出至少三个常见错误及解决方案。
7. **文档索引**：指向 `e-docs/` 中对应的详解文档。

> 可参考 `e-voice-admin/README.md` 和 `e-voice-admin-front/README.md` 的写法，在 README 中补充文档链接。 【F:e-voice-admin/README.md†L55-L145】【F:e-voice-admin-front/README.md†L4-L37】

## 4. API 文档要求

- 在子系统文档或独立 API 文档中，使用统一表格格式说明接口：

| 接口 | 方法 | 请求参数 | 返回字段 | 处理逻辑 |
| --- | --- | --- | --- | --- |
| `/voice/print/saveUserPrint` | POST | `audio`（文件）、`userId`、`userName` | 声纹向量、识别文本 | 调用 Python `/voice-register`，成功后返回处理信息。 |

- 若接口需要图示流程，可补充时序图或流程图解释前端/后端交互。
- 对外开放的接口需标注鉴权方式（例如 JWT、签名参数）和速率限制。

## 5. 更新流程

1. **代码改动**涉及接口、数据流、配置时，需同步更新对应子系统文档与 README。  
2. **文档新增/更新**后，在 Pull Request 中说明调整范围，并在 `总体架构与说明` 的“文档体系”列表中添加新条目（如适用）。  
3. 文档内容需保持与主干代码一致，发布新版本时请检查引用的行号是否仍然有效。

## 6. 版本记录建议

- 在文档末尾可追加“更新记录”表，记录日期、作者、变更内容。  
- 若文档对应的功能存在重大变更，需在项目 CHANGELOG 中同步提及。

## 7. 质量校验

- 提交前确认 Markdown 可正确渲染表格、代码块与流程图。  
- 引用链接（如流程图、附加资源）需使用相对路径，保证在离线环境下可访问。  
- 如需引用图片，请将资源存放在 `e-docs/assets/` 或同目录 `assets/` 子文件夹并在文档中引用相对路径。

---

遵循以上规范可以确保文档内容完整、结构统一，为后续维护、排查与知识沉淀提供一致的入口。
