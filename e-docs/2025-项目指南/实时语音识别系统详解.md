## 一、系统架构概览

E-Voice实时语音识别系统采用**WebSocket + 流式AI模型**的架构，实现了"边说边识别"的输入法风格体验。系统分为以下核心组件：

### 后端服务 (Python)

- **WebSocket服务器**: `/ws/recognize` endpoint
- **流式识别引擎**: StreamingEngine
- **会话管理器**: StreamingSessionManager
- **FunASR模型集成**: ModelLoader

**核心文件**:
- `e-voice/server/routes/ws.py` - WebSocket路由处理
- `e-voice/speech_recognition/streaming/engine.py` - 识别引擎
- `e-voice/speech_recognition/streaming/state.py` - 会话状态
- `e-voice/speech_recognition/streaming/text_accumulator.py` - 文本累加器
- `e-voice/speech_recognition/streaming/loader.py` - 模型加载器

### 前端客户端 (Vue/HTML)

- **WebSocket客户端连接**
- **音频采集** (Web Audio API)
- **实时文本渲染**

**核心文件**:
- `e-voice-admin-front/src/views/voice/print/RealtimeForm.vue` - Vue组件
- `e-voice/tests/pages/speech-recognition-test.html` - 测试页面

### 2.2 音频流处理阶段

**文件**: `e-voice/server/routes/ws.py:158-173` + `speech_recognition/streaming/engine.py:21-69`

```

     ↓

     ↓
```

### 2.3 VAD (语音端点检测) 逻辑

**文件**: `e-voice/server/routes/ws.py:65-75`

```python
def _run_vad(state, bundle, audio_chunk):
    if bundle.vad is None:
        return False

    # FunASR VAD推理
    result = bundle.vad.generate(input=audio_chunk, **state.vad_state)[0]["value"]
    state.vad_state = result.get("cache", state.vad_state)  # 保持状态连续性

    # 检测是否语音结束
    if result and isinstance(result, list) and result[0][1] != -1:
        return True  # 检测到语音结束
    return False
```

**VAD触发机制**:
- 检测到`speech_end=True` → 自动触发`engine.flush()` → 生成最终识别结果
- 对应前端停顿1.5秒自动确认句子的体验

### 2.4 双模式识别引擎

**文件**: `e-voice/speech_recognition/streaming/engine.py`

#### 在线流式识别 (push方法)

```python
# engine.py:21-69
def push(self, audio_chunk: bytes, state: StreamingState) -> List[dict]:
    state.pending_audio.append(audio_chunk)
    state.pending_offline_audio.append(audio_chunk)  # 同时缓存用于离线

    # 在线ASR推理 (paraformer-zh-streaming)
    audio_bytes = b"".join(state.pending_audio)
    result = self._bundle.online_asr.generate(
        input=audio_bytes,
        **state.online_cache  # 保持推理上下文
    )[0]

    partial_text = result["text"]
    state.online_cache = result.get("cache", state.online_cache)  # 更新缓存

    # 文本累加器处理
    accumulator = state.text_accumulator
    revision = state.next_revision()  # 修订版本号+1
    snapshot = accumulator.update_partial(partial_text, revision)

    # 返回partial事件
    event = {
        "type": "partial",
        "mode": "realtime",
        "text": partial_text,
        "is_final": False,
        "segment_id": state.ensure_segment(),
        "text_state": snapshot,  # 包含confirmed_text和candidate_text
        "revision": revision
    }

    state.pending_audio.clear()  # 清空已处理音频
    return [event]
```

**特点**:
- **流式推理**: 每次收到音频块立即推理，无需等待
- **状态保持**: `online_cache`维护模型内部状态，支持连续识别
- **修订追踪**: `revision_id`递增，前端用于排序防止乱序

#### 离线精准识别 (flush方法)

```python
# engine.py:71-125
def flush(self, state: StreamingState) -> Iterable[dict]:
    audio_bytes = b"".join(state.pending_offline_audio)
    state.pending_offline_audio.clear()

    # 离线ASR推理 (更高准确率)
    offline_result = self._bundle.offline_asr.generate(
        input=audio_bytes,
        **state.offline_cache
    )[0]
    text = offline_result.get("text", "")

    # 标点恢复
    if self._bundle.punc:
        punc_result = self._bundle.punc.generate(input=text)[0]
        text = punc_result.get("text", text)

    # 逆文本规范化 (数字口语化)
    if self._bundle.itn:
        itn_result = self._bundle.itn.generate(input=text)[0]
        text = itn_result.get("text", text)

    # 文本纠错累加
    accumulator = state.text_accumulator
    snapshot = accumulator.apply_correction(text)  # 计算diff

    # 返回correction事件
    event = {
        "type": "correction",
        "mode": "offline",
        "text": text,
        "is_final": True,
        "segment_id": state.ensure_segment(),
        "text_state": snapshot,  # 包含changes详细差异
        "revision": state.revision
    }

    return [event]
```

**特点**:
- **延迟推理**: 等待语音结束后统一处理
- **多模型链**: ASR → 标点恢复 → 文本规范化
- **高准确率**: 牺牲实时性换取更准确的结果

### 2.5 文本状态管理

**文件**: `e-voice/speech_recognition/streaming/text_accumulator.py`

TextAccumulator维护两种文本状态:

```python
@dataclass
class TextAccumulator:
    confirmed_text: str = ""      # 已确认文本 (黑色正体)
    candidate_text: str = ""      # 候选文本 (蓝色斜体)
    revision_id: int = 0          # 修订版本号
    history: List[Dict] = None    # 历史记录
```

#### 关键方法

**1. update_partial** (partial事件调用)

```python
def update_partial(self, text: str, revision: int):
    self.candidate_text = text  # 更新候选区
    self.revision_id = revision
    return {
        "confirmed_text": self.confirmed_text,
        "candidate_text": self.candidate_text,
        "revision_id": self.revision_id
    }
```

**2. apply_correction** (correction事件调用)

```python
def apply_correction(self, text: str):
    # 使用SequenceMatcher计算编辑距离
    changes = self.diff_detailed(text)  # [{'type':'delete/insert/replace', ...}]

    self.confirmed_text = text  # 纠正后的文本进入确认区
    self.candidate_text = ""    # 清空候选区
    self.revision_id += 1

    return {
        "confirmed_text": self.confirmed_text,
        "candidate_text": self.candidate_text,
        "revision_id": self.revision_id,
        "changes": changes  # 详细差异列表
    }
```

**输入法风格实现原理**:
- `confirmed_text`: 像手机输入法的已输入文本 (不可修改)
- `candidate_text`: 像输入法的候选栏 (实时变化)
- 停顿触发VAD → flush → candidate变为confirmed

### 2.6 事件排序与防乱序机制

**文件**: `e-voice/server/routes/ws.py:78-110`

```python
def _send_events(ws, events, state, request_id):
    # ✅ P0-1修复: 按revision_id严格排序
    events_list = list(events or [])
    events_list.sort(key=lambda e: e.get('text_state', {}).get('revision_id', 0))

    for event in events_list:
        event.setdefault("session_id", state.session_id)
        event.setdefault("request_id", request_id)
        event.setdefault("segment_id", state.ensure_segment())

        # 添加时间戳
        timestamps = event.setdefault("timestamps", {})
        timestamps.setdefault("event_ms", int(time.time() * 1000))

        # 添加元数据
        metadata = event.setdefault("metadata", {})
        if state.hotwords:
            metadata.setdefault("hotwords", sorted(state.hotwords.keys()))

        ws.send(json.dumps(event))
```

**防乱序关键**:
- 所有事件按`revision_id`排序后发送
- 前端也按`revision_id`渲染，避免文本闪回

## 三、前端实现分析

### 3.1 音频采集链路

**文件**: `e-voice/tests/pages/speech-recognition-test.html:771-864`

```javascript
// 获取麦克风权限
const stream = await navigator.mediaDevices.getUserMedia({
    audio: {
        sampleRate: 16000,      // 16kHz采样率
        channelCount: 1,         // 单声道
        echoCancellation: true,  // 回声消除
        noiseSuppression: true,  // 降噪
        autoGainControl: true    // 自动增益
    }
});

// 创建AudioContext
audioContext = new AudioContext({ sampleRate: 16000 });
const source = audioContext.createMediaStreamSource(stream);

// 使用ScriptProcessor处理音频 (4096 buffer)
scriptProcessor = audioContext.createScriptProcessor(4096, 1, 1);

scriptProcessor.onaudioprocess = function(event) {
    const inputData = event.inputBuffer.getChannelData(0);  // Float32Array

    // 计算RMS (音频能量)
    const rms = Math.sqrt(inputData.reduce((sum, sample) =>
        sum + sample * sample, 0) / inputData.length);

    // 静音检测 (避免发送无效数据)
    if (rms < 0.01) {
        return;  // 跳过静音帧
    }

    // Float32 → Int16 PCM转换
    const pcmData = new Int16Array(inputData.length);
    for (let i = 0; i < inputData.length; i++) {
        let sample = Math.max(-1, Math.min(1, inputData[i]));
        pcmData[i] = sample < 0 ? sample * 0x8000 : sample * 0x7FFF;
    }

    // 转换为Base64
    const buffer = new ArrayBuffer(pcmData.length * 2);
    const view = new DataView(buffer);
    for (let i = 0; i < pcmData.length; i++) {
        view.setInt16(i * 2, pcmData[i], true);  // little endian
    }

    const uint8Array = new Uint8Array(buffer);
    const base64Data = btoa(String.fromCharCode.apply(null, uint8Array));

    // 通过WebSocket发送
    websocket.send(JSON.stringify({
        type: 'chunk',
        audio: base64Data,
        format: 'pcm',
        sample_rate: 16000,
        rms: rms.toFixed(4)
    }));
};

// 连接音频处理链
source.connect(scriptProcessor);
scriptProcessor.connect(audioContext.destination);
```

**音频处理关键点**:
- **采样率统一**: 前端16kHz → 后端模型16kHz
- **数据类型转换**: Float32 → Int16 PCM → Base64
- **静音优化**: RMS < 0.01时减少发送频率
- **实时性**: 4096帧 ≈ 256ms延迟

### 3.2 消息处理与UI渲染

**文件**: `e-voice/tests/pages/speech-recognition-test.html:656-747` + `e-voice-admin-front/src/views/voice/print/RealtimeForm.vue:147-189`

```javascript
websocket.onmessage = function(event) {
    const data = JSON.parse(event.data);

    switch (data.type) {
        case 'partial':
            // 实时识别 - 更新候选区
            const state = data.text_state || {};
            const confirmed = state.confirmed_text || '';
            const candidate = state.candidate_text || data.text || '';

            if (confirmed) {
                document.getElementById('finalText').textContent = confirmed;
            }

            if (candidate) {
                const partialText = document.getElementById('partialText');
                partialText.textContent = candidate;
                partialText.style.color = '#007bff';     // 蓝色
                partialText.style.fontStyle = 'italic';  // 斜体
            }
            break;

        case 'correction':
        case 'final':
            // 最终确认 - 迁移到确认区
            const finalState = data.text_state || {};
            const confirmedText = finalState.confirmed_text || data.text;

            if (confirmedText) {
                document.getElementById('finalText').textContent = confirmedText;
            }

            // 清空候选区,准备下一句
            const partialText = document.getElementById('partialText');
            partialText.textContent = '正在监听...';
            partialText.style.color = '#007bff';
            partialText.style.fontStyle = 'normal';

            // 自动滚动到最新内容
            document.getElementById('finalText').scrollTop =
                document.getElementById('finalText').scrollHeight;
            break;

        case 'error':
            console.error('识别错误:', data.message);
            break;
    }
};
```

**UI渲染逻辑**:
- **双区域显示**:
  - 实时区 (partialText): 蓝色斜体，显示正在说的话
  - 确认区 (finalText): 黑色正体，显示已确认的文本
- **自动确认**: VAD检测停顿 → correction事件 → 候选区迁移到确认区
- **连续识别**: 确认后清空候选区，可以继续说下一句

```python
def load(self) -> ModelBundle:
```

## 五、会话管理机制

**文件**: `e-voice/server/services/streaming_session.py`

```python
class StreamingSessionManager:
    _instance = None  # 单例

    def __init__(self):
        self._sessions: dict[str, SessionContext] = {}
        self._lock = Lock()  # 线程安全
        self._metrics = StreamingMetrics()  # 性能监控

    def create_session(self, context: SessionContext):
        with self._lock:
            self._sessions[context.session_id] = context
            self._metrics.active_sessions = len(self._sessions)

    def close_session(self, session_id: str):
        with self._lock:
            self._sessions.pop(session_id, None)
            self._metrics.active_sessions = len(self._sessions)

    def get_session(self, session_id: str) -> Optional[SessionContext]:
        with self._lock:
            return self._sessions.get(session_id)
```

```python
@dataclass
class SessionContext:

    state: StreamingState        # 识别状态 (音频缓存/模型状态)
```

## 七、关键技术特性

### 7.1 双模式识别 (2-Pass)

- **Online模式**: 流式推理,延迟<200ms,准确率85-90%
- **Offline模式**: 批量推理,延迟1-2s,准确率95-98%
- **自动切换**: VAD检测停顿自动触发offline模式

### 7.2 状态连续性

- **online_cache**: 维护在线ASR的内部状态 (Transformer hidden states)
- **vad_state**: VAD模型的状态缓存
- **pending_audio**: 累积的音频buffer
- **segment_id**: 句子级别的唯一标识

### 7.3 文本修订机制

- **revision_id**: 单调递增的修订版本号
- **排序保证**: 所有事件按revision_id排序,防止乱序
- **差异计算**: SequenceMatcher计算编辑距离,提供详细变更列表

### 7.4 性能优化

- **GPU加速**: 自动检测GPU并分配 (device: auto)
- **线程池**: 离线ASR使用4线程并发
- **缓存清理**: 推理后调用`torch.cuda.empty_cache()`
- **静音检测**: 前端RMS<0.01时减少发送频率

## 附录C: 常见问题排查

### Q1: 连接建立失败

**症状**: WebSocket连接超时或立即关闭

**排查步骤**:
1. 检查服务器地址配置 (`wsHost`)
2. 确认Python后端服务已启动 (端口8210)
3. 检查防火墙/代理设置
4. 查看浏览器控制台错误信息

**日志位置**: `logs/ws.log`

### Q2: 没有识别结果

**症状**: 麦克风正常但无文本输出

**排查步骤**:
1. 检查模型是否加载成功 (`ModelLoader.current().load()`)
2. 确认音频格式正确 (16kHz PCM)
3. 检查RMS是否过低 (静音检测阈值)
4. 查看 `logs/recognition_results.log`

**常见原因**:
- 模型未下载完整
- GPU内存不足
- 音频编码错误

### Q3: 识别延迟过高

**症状**: 说话后3-5秒才显示文字

**排查步骤**:
1. 检查GPU是否可用 (`device: auto`)
2. 调整 `chunk_interval_ms` (降低到20ms)
3. 减少 `offline_thread_pool` (避免CPU竞争)
4. 查看 `logs/ws.log` 中的推理时间

**优化建议**:
- 使用GPU加速
- 减少并发会话数
- 升级硬件配置

### Q4: 文本乱序或闪回

**症状**: 已确认的文本突然被修改

**排查步骤**:
1. 检查前端是否按 `revision_id` 排序
2. 确认 `_send_events` 中的排序逻辑
3. 查看控制台是否有异常事件

**修复方案**:
- 已实现P0-1修复 (revision_id排序)
- 确保前端渲染逻辑正确
