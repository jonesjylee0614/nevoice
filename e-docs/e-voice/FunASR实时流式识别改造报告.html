FunASR 实时流式识别改造报告

针对“实时识别结果只剩最后一个词、无法累计显示且缺少自动纠错”的问题，完成 FunASR 流式管线、文本缓冲与前端呈现的系统级重构。

1. 问题复盘

  • 单缓冲覆盖：流式回调每次以 text 覆盖 full_sentence，导致 UI 与日志只保留最后一个片段。
  • Final 仅返回末尾 token：句尾刷新时直接使用 FunASR 缓存的最后一次回包，最终句只剩“上线”。
  • 缺少语义纠错：未集成领域热词与中文自动纠错，行业词“字节跳动、推荐引擎”等易被错识。
  • 日志乱序与状态不明：缺乏段落编号/版本号，无法定位“谁覆盖了谁”。

2. 核心改造

双缓冲文本状态session.py

  • 新增 committedText/liveText（确认区 + 候选区）状态机。
  • 引入 segment_id + revision，前后端共享段落版本。
  • 日志打印合并文本：[streaming] seg=xxx rev=yyy。

流式 + 离线混合裁决FunASR

  • 每个句尾执行 FunASR flush + Paraformer 离线全量识别。
  • 根据文本长度与相似度优先选择更完整的一侧，解决“只剩最后一个词”。
  • 保留处理延迟信息，便于监控性能。

自动纠错链路zh_correct

  • 将 PyCorrector 封装成幂等工具，自动加载词频词典。
  • 句尾仅对最终文本纠错，避免部分识别闪烁。
  • 响应中返回 auto_correction & raw_text 便于 UI 呈现差异。

前端双层展示RealtimeForm.vue

  • 改用 committedText + liveText 组合渲染。
  • 实时展示段落编号 rev，最终句保留在历史区域。
  • 自动纠错时提示“raw → corrected”。

4. 响应结构对照

字段 说明 用途
segment_id, revision 段落号 + 增量版本，用于乱序保护与日志排查。 防止旧 partial 覆盖最新文本。
text_state.full_text 确认 + 候选合并后的完整文本。 前端直接展示给用户，仿输入法体验。
auto_correction 纠错明细（被改词、位置等）。 供 UI 或日志高亮提示。
raw_text 纠错前的文本快照。 对比验证纠错效果。

5. 验收要点

  1. 朗读长句时，partial 按 seg/rev 连续输出，历史文本不被覆盖。
  2. Final 输出完整句子：“今日头条是北京字节跳动科技有限公司…”，而非“上线”。
  3. 日志同步打印：[streaming] seg=abcd rev=5: '今日头条…'。
  4. UI 顶部显示确认文本，底部滚动候选文本，句尾清空候选。
  5. 纠错命中时响应含 auto_correction_applied=true 且日志记录“raw → corrected”。
