## 🎯 核心问题与解决方案

### 问题 1: 事件顺序混乱

**症状**:
- 前端收到的 `partial` 和 `correction` 事件乱序
- 文本频繁闪回、跳跃
- 用户体验差

**根因**:
```python
# ws.py:_send_events() 未对事件排序
for event in events or []:
    ws.send(json.dumps(event))
```

**解决方案**:
```python
# 按 revision_id 严格排序
events_list = list(events or [])
events_list.sort(key=lambda e: e.get('text_state', {}).get('revision_id', 0))
```

**效果**:
- ✅ 消除文本闪回
- ✅ 事件按版本号有序发送
- ✅ 前端渲染流畅

---

### 问题 2: 前端缺乏时序保护

**症状**:
- 快速语音时，纠错文本被后续 partial 覆盖
- 旧结果覆盖新结果

**根因**:
```javascript
// 直接覆盖，不检查版本
partialBox.innerHTML = text;
```

**解决方案**:
```javascript
let lastRevision = 0;

function renderPartialText(data) {
    const revision = (data.text_state && data.text_state.revision_id) || 0;
    if (revision < lastRevision) {
        console.warn('丢弃过期事件');
        return;  // 不渲染过期事件
    }
    lastRevision = revision;
    // 正常渲染...
}
```

**效果**:
- ✅ 防止旧结果覆盖新结果
- ✅ 日志显示丢弃的过期事件
- ✅ 快速语音下表现稳定

---

### 问题 3: segment_id 管理不当

**症状**:
- 同一句话的 partial 和 correction 使用不同 segment_id
- 日志混乱，难以追踪

**根因**:
```python
# ws.py 中重复调用 ensure_segment()
if event.get("type") == "correction":
    segment_id = event.get("segment_id") or state.ensure_segment()
else:
    segment_id = event.get("segment_id") or state.ensure_segment()
```

**解决方案**:
```python
# 简化逻辑，engine 中已设置
event.setdefault("segment_id", state.ensure_segment())
```

**关键改进**:
- `engine.py` 的 `push()` 和 `flush()` 都调用 `state.ensure_segment()`
- `ensure_segment()` 保证在同一段落返回相同 ID
- `mark_segment_final()` 在段落结束时清空 ID

**效果**:
- ✅ 同一句话的事件使用相同 segment_id
- ✅ 代码逻辑更清晰
- ✅ 易于调试和追踪

---

### 问题 4: 差异算法过于简单

**症状**:
- 纠正提示不准确
- 无法识别中间插入/删除

**根因**:
```python
# 简单前缀匹配
prefix_len = 0
for old_ch, new_ch in zip(self.confirmed_text, new_text):
    if old_ch != new_ch:
        break
    prefix_len += 1
removed = self.confirmed_text[prefix_len:]
appended = new_text[prefix_len:]
```

**示例问题**:
```
原文: "今天天气真好"
纠正: "今天的天气真不错"

旧算法误判：
  删除 "天气真好"
  新增 "的天气真不错"

实际应该：
  位置2插入 "的"
  位置6替换 "好" → "不错"
```

**解决方案**:
```python
from difflib import SequenceMatcher

def diff_detailed(self, new_text: str) -> List[Dict[str, Any]]:
    matcher = SequenceMatcher(None, self.confirmed_text, new_text)
    changes = []

    for tag, i1, i2, j1, j2 in matcher.get_opcodes():
        if tag == 'delete':
            changes.append({
                'type': 'delete',
                'text': self.confirmed_text[i1:i2],
                'position': i1,
                'length': i2 - i1,
            })
        elif tag == 'insert':
            # ... 插入操作
        elif tag == 'replace':
            # ... 替换操作

    return changes
```

**效果**:
- ✅ 精确到字符级别的差异
- ✅ 支持 delete、insert、replace 三种操作
- ✅ 前端可获取详细编辑列表

### 问题 5: 音频分块不规范

**症状**:
- 识别结果抖动
- 不如 FunASR 官方 demo 稳定

**根因**:
```javascript
// 每 4096 samples (256ms) 发送一次
const bufferSize = 4096;
scriptProcessor.onaudioprocess = function(event) {
    // 立即发送
    websocket.send(audioData);
};
```

**FunASR 官方推荐**:
```python
chunk_size = [0, 10, 5]  # 600ms 延迟配置
chunk_stride = 10 * 960  # 9600 samples
```

**解决方案**:
```javascript
const CHUNK_STRIDE = 9600;  // 600ms @ 16kHz
let audioBuffer = [];

scriptProcessor.onaudioprocess = function(event) {
    // 累积音频
    audioBuffer.push(...input);

    // 达到 CHUNK_STRIDE 时发送
    while (audioBuffer.length >= CHUNK_STRIDE) {
        const chunk = audioBuffer.slice(0, CHUNK_STRIDE);
        audioBuffer = audioBuffer.slice(CHUNK_STRIDE);
        sendAudioChunk(chunk);
    }
};
```

**效果**:
- ✅ 对齐 FunASR 官方推荐
- ✅ 减少网络传输频率（-58%）
- ✅ 识别结果更稳定
