# 实时识别 + 智能纠错 P0 需求锁定记录

> 目标：在 nevoice 环境内复刻 FunASR WebSocket 2pass 架构前，完成协议/性能指标对齐与 POC 可行性验证。

## 1. 协议与消息体对齐

- **官方参考**：`FunASR/runtime/python/websocket/funasr_wss_server.py`、`FunASR/runtime/docs/websocket_protocol_zh.md`。
- **消息类型**：`start`、`audio`/`binary`、`control`、`final`、`2pass-online`、`2pass-offline`、`error`、`close`。
- **字段映射**：
  - `mode` → 支持 `online`、`2pass`、`offline`；默认 `online`。
  - `chunk_interval`、`hotwords`、`speaker_id`、`app_key` 等控制字段需要透传。
  - 输出字段需包含 `request_id`、`session_id`、`segment_id`、`is_final`、`timestamps`、`latency_ms`。
- **差异点**：现有 v1 方案使用 JSON 封装 base64 音频，需要改为二进制帧，并增加 `control` 消息处理。
- **Action**：编制对照表，供 P1 `ws_v2.py` 开发使用；同时预留 `开放接口设计.md` 新增实时识别 v2 小节所需字段描述。

## 2. 性能与并发目标

- **延迟**：在线输出 < 500ms、纠错 < 2s；压测目标 ≥ 50 并发会话。
- **资源估算**：
  - Online Paraformer GPU 显存 ~3GB；Offline Paraformer ~7GB；Punc/ITN <1GB。
  - 建议使用单卡 16GB 显存或 A10G 等配置；需预留 CPU 线程用于离线纠错。
- **Action**：和运维确认可用 GPU/CPU 规格，约定压测场景（长语音、嘈杂环境）。

## 3. FunASR Demo POC 准备

- **环境依赖**：Python 3.9+/Torch 1.13+/CUDA 11.7+；需安装 `FunASR` 最新 release。
- **模型列表**（与线上目标一致）：
  - Online ASR：`paraformer-zh-streaming`（或最新 streaming 版本）。
  - Offline ASR：`paraformer-zh-offline`。
  - VAD：`fsmn-vad`。
  - Punc：`ct-punc`。
  - ITN：`zh-itn`。
- **验证步骤**：
  1. 在测试环境部署 FunASR demo WebSocket 服务。
  2. 使用官方客户端推送样例音频，记录 online/2pass 输出及延迟。
  3. 抓取协议报文，归档到 `tests/data/funasr_demo_protocol/`。
- **Action**：准备执行脚本（部署命令、客户端调用），并形成 POC 报告草稿。

## 4. 与现有系统的接口边界

− 旧版 `RealtimeSpeechSession`/`ws.py` 已淘汰，仅保留新的 `ws_v2` 实现。
− 新方案需兼容 `request_id` 来源（REST 网关 / Admin 颁发）。
- 需要确认是否复用当前 Redis/MQ 组件；若阶段内不接入，则先保留空实现。
- **Action**：同业务方确认热词、声纹扩展字段的上下游依赖。
