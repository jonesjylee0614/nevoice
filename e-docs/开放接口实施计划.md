# nevoice 开放接口实施计划

## 1. 背景与目标

- 《开放接口设计.md》已对外发布，目前仍引用 FunASR 示例。我们需要在 **nevoice** 代码库内完整实现并维护这些接口，让 FunASR 仅作为底层模型能力的参考实现。
- 现状是“部分接口已经实现、部分实现有缺陷、部分尚未落地”。本计划梳理现有资产，明确实现路线、代码规范与文件规划，确保开放接口的交付具备一致性、安全性与可运维性。

## 2. 现状梳理

### 2.1 已有能力（不完全符合规范）
- `nevoice/e-voice/server/routes/voice.py` 已提供声纹注册、离线/在线识别的基础处理，但缺少统一响应体、鉴权、任务管理与错误码。
- WebSocket 实现散落在 `server/routes/socketio_events.py` 与 `server/routes/ws.py`，消息格式与开放规范存在差异，且未实现鉴权与重启恢复策略。
- 声纹入库逻辑依赖 `es.voice.insert_voice` 与 `pipeline.spk_v_pipeline.embedding`，可复用但缺缺乏 REST API 封装。
- 管理端（`e-voice-admin`、`e-voice-admin-front`）已有基础 Go/Vue 框架，但未接入开放接口相关的配置、审计、限流。

### 2.2 缺口与风险
1. **接口缺失**：开放文档中的离线任务管理、实时识别帧协议、声纹管理 CRUD、热词配置等均未在 nevoice 中对应落地。
2. **统一响应/错误码缺失**：当前接口直接返回 Flask 默认结构或字符串，未遵循 `{code,message,data}`。
3. **鉴权与限流**：`x-ak/x-t/x-sign` 未实现，亦缺重放防护、IP 白名单。
4. **任务生命周期**：缺少 job 表、存储层、异步执行器与回调机制。
5. **测试与文档**：没有可复用的集成测试或 OpenAPI 描述，导致前后端对接成本高。

## 3. 功能范围（与开放接口对齐）
1. **REST 离线识别**
   - `POST /v1/voice/offline/jobs`（上传音频 + 元数据）
   - `GET /v1/voice/offline/jobs/{job_id}`（状态/结果）
   - 可选 `DELETE /v1/voice/offline/jobs/{job_id}`（取消）
2. **实时 WebSocket 识别**
   - 握手鉴权、音频帧推送、实时/最终结果、错误通知。
3. **声纹管理**
   - 注册、识别、列表、删除与多租户隔离。
4. **辅助接口**
   - 系统健康检查、热词配置、回调重试、日志追踪、错误码兜底。

## 5. 代码规范

### 5.1 Python（e-voice）
1. **格式化**：`black --line-length 100` + `isort`；提交前运行 `pytest`、`ruff`.
2. **结构**：接口层只做参数校验、调用 service；业务逻辑放在 `server/services/*`；数据层统一 `biz`/`db`.
3. **类型**：新增模块必须启用 `from __future__ import annotations`，函数提供类型提示；序列化对象使用 `dataclasses`/`pydantic`.
4. **响应规范**：所有 REST/WS 返回 `{"code": int, "message": str, "data": Any, "request_id": str}`，错误码集中定义在 `server/errors.py`.
5. **日志与追踪**：借助 `loguru` 添加 `request_id`、`job_id`、`tenant_id`，禁止直接 `print`.

### 5.2 Go（e-voice-admin）
1. 使用 `gofmt`、`goimports`；lint 通过 `golangci-lint`.
2. 新增开放接口管理模块放入 `internal/app/openapi`，公共组件放入 `internal/pkg`.
3. REST 调用开放接口时必须带上 `context.Context`，日志字段包含 `tenant_id/request_id`.

### 5.3 前端（e-voice-admin-front）
1. 保持 `pnpm lint`, `pnpm type:check` 全过；使用 `<script setup lang="ts">`
2. 新增页面放在 `src/views/openapi/*`，接口封装放 `src/api/openapi.ts`，常量放 `src/constants/openapi.ts`.

### 5.4 文档与测试
1. 所有接口在 `e-docs/SDK相关/接口文档` 与 `docs/openapi.yaml` 中同步更新。
2. 测试目录规划：`tests/offline_jobs`, `tests/ws`, `tests/voiceprint`, 集成测试命名 `test_<feature>_integration.py`.

## 7. 依赖与 FunASR 协同
- **模型复用**：继续依赖 FunASR `Paraformer`/`SenseVoice` 等模型；通过 `requirements.txt` 锁定版本，并在 `speech_recognition` 中提供统一的模型加载工厂。
- **更新策略**：FunASR 升级需要回归开启（Phase 5），并在 `docs/changelog.md` 标注对开放接口的影响。
- **共用脚本**：保留 `finetune.sh`、`mvmodel.sh` 以便模型迁移，但执行逻辑迁移到 `resource/models/README.md` 统一说明。

## 8. 风险与缓解
1. **GPU/CPU 资源**：Phase 2/3 压测需要独立 GPU，需提前向运维申请；提供降级策略（CPU 模式 + 队列限流）。
2. **数据合规**：声纹数据涉及敏感信息，必须按租户隔离并提供删除 API；日志中屏蔽 PII。
3. **兼容历史接口**：当前 `/voice-recognize-*` 仍在使用，需通过 API Gateway 做路径兼容或在代码内保留旧路由，待开放接口稳定后再公告下线。
